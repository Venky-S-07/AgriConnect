## 1. Key Accomplishments

1. **Robust Farmer Context Store:**
   Engineered clean relational models linking `Farmer`, `Farm`, and `CropOnFarm` with enforced foreign-key constraints and automated cascade deletions.
2. **Dialect-Safe SQLite Foreign Key Enforcement:**
   Implemented the approved engine-instance event listener pattern strictly executed on SQLite engines (`if engine.dialect.name == "sqlite"`), avoiding brittle global listener monkey-patching or private attribute inspection.
3. **Stateless Minimal JWT Authentication:**
   Eliminated PII from tokens. Payloads strictly consist of `sub` and `exp`. Required mandatory `SECRET_KEY` validation on startup lifespan, refusing execution if secrets are missing or short, with `.env` git-ignored and `.env.example` committed.
4. **Principled Consent Governance:**
   Architected dual-consent tracking separating general data-processing consent from optional image-training consent. Supported authenticated consent withdrawal with an operational guard (HTTP 403 on write mutations while preserving HTTP 200 on read-only endpoints).
5. **Rigorous Farm Parcel & Irrigation Validation:**
   Enforced strict cross-field validation rules preventing contradictory configurations (such as rainfed farms declaring pump rates or pressurized irrigation types) and requiring provenance (`MEASURED`, `FARMER_ENTERED`, `ESTIMATED`) for pump discharge rates.
6. **Curated Regional Crop Catalog:**
   Created a centralized JSON catalog of 10 regional Indian crops with canonical slugs, duration days, and valid growth stages in English and Kannada. Prevented concurrent active crops on the same parcel while providing clean soft-deactivation.
7. **Comprehensive Test Automation & Verification:**
   Authored 30 comprehensive backend unit and integration tests covering cascades, tenant isolation, cross-field validation, and privacy export. Built a standalone 17-step end-to-end verification harness.

## 2. Key Architectural Decisions (ADRs)

### ADR-M2-01: Engine-Instance Event Listener for SQLite Foreign Keys
- **Context:** SQLite disables foreign key enforcement by default. SQLAlchemy connections need `PRAGMA foreign_keys=ON;`.
- **Decision:** Bind `@event.listens_for(engine, "connect")` directly to the `engine` instance gated by `if engine.dialect.name == "sqlite":`.
- **Consequences:** Clean dialect isolation. Skips execution automatically if switched to PostgreSQL in production. Avoids relying on internal `_engine` connection record attributes.

### ADR-M2-02: Zero-PII Minimal JWT Payload
- **Context:** Storing user information (phone number, name, location) inside JWT payloads leads to PII leakage and stale context.
- **Decision:** Include only `sub` (string representation of `farmer_id`) and `exp` in JWT tokens. Require database lookup via `get_current_farmer` dependency for up-to-date context and consent verification.
- **Consequences:** Maximum privacy, immediate revocation recognition upon account deletion, and minimal token footprint.

### ADR-M2-03: Dual-Consent Segregation with Read-Preserving Withdrawal
- **Context:** Farmers must be empowered to withdraw consent without losing visibility into their historic records, while halting active automated decision processing.
- **Decision:** Segregate mandatory general data-processing consent from optional image-training consent. When general consent is withdrawn, return HTTP 403 on operational creation/update endpoints (`require_active_consent`), but maintain HTTP 200 on read-only endpoints (`get_current_farmer`).
- **Consequences:** Adheres to progressive privacy principles without destructive or unintended data loss prior to explicit account deletion.

### ADR-M2-04: Centralized JSON Crop Knowledge vs Database Table
- **Context:** Crop catalog contains regional agronomic reference data (stages, durations, names).
- **Decision:** Store the reference catalog in version-controlled `crops_catalog.json` with helper validator functions rather than a dynamic database table.
- **Consequences:** Fast read performance, version-controllable agronomic data, deterministic stage validations, and zero database migration overhead for catalog updates.

## 3. Tech Learnings & Gotchas

1. **Pydantic V2 Configuration:**
   - Switched from deprecated `class Config: from_attributes = True` to Pydantic V2's `model_config = ConfigDict(from_attributes=True)`.
2. **SQLite Cascade Testing Across Runs:**
   - Tests creating records with fixed unique constraints (e.g. phone numbers) must ensure idempotent pre-test cleanup to avoid collisions when the SQLite database persists on disk across repeated test runs.
3. **Sandbox Localhost Port Isolation on Windows:**
   - On Windows, services listening on localhost within sandboxed processes require specific permissions; automated E2E harnesses running live HTTP clients against local uvicorn instances should execute with network bypass.
